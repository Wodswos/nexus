# Task 多选与批量操作设计

日期：2026-11-10。状态：**部分实施：导图与列表已接入时间、优先级、任务／分组转换和整批折叠，其余为设计目标**。适用于 Nexus（历史名 Cortex）的列表、导图、四象限、甘特图、日历，以及承载这些视图的当前任务、项目和快捷视图工作区。

本文承接 [整体交互设计](INTERACTION_DESIGN.md)，记录代码现状、推荐范围、关键行为与验收标准。不能将本文中的目标能力理解为当前线上已经支持。

### 已实施的第一步

- 导图框选、修饰键多选后，选择条直接提供「时间」「优先级」「样式」。列表原有多选条也加入同一批量设置入口。
- 导图只在拖动框选时显示范围框，松开后隐藏 React Flow 的持久多选遮罩，仅保留节点选中标记。隐藏遮罩同时取消其点击拦截；右击已选节点或有选区的画布均打开整批菜单。
- 右击已选任务保留整批；右击选区外的任务只操作该项，避免把旧选区意外加入。
- 时间面板可分别保持、设置或清除开始／截止，提供整批清除及按日历天整体提前／顺延；时刻留空保留各自时分。只有点击「应用」才写入，取消、Esc、点击外部均放弃草稿。
- 优先级显式设为 P0–P3，显示混合值及预计修改数。项目／分组不接收日期和优先级；整体移动另外排除无排期任务。
- `planTaskBatch` 先验证全部日期，再由 `NexusStore.setTaskBatch` 在一个 Yjs 事务和独立撤销单元写入实际变化字段。保留未选子任务、完成状态、关联日程和其他字段。
- 面板冻结目标 ID，提交前检查相关字段有无并发修改；发现冲突则整批不写。应用后显示实际修改数与撤销说明，本地保存失败明确提示已应用，不重复执行。
- 多选菜单移除创建子任务、详情和跳转等单项入口，提供明确的「转为分组」「转为 Task」及可修改数量。`setTaskKinds` 去重后一次事务、一项撤销；跳过项目、已删除、归档及同类型项，保留其他字段和未选后代。普通顶层项转为分组显式保持 `project=false`，不创建新项目。
- 类型转换保留原状态、完成时间、排期、优先级与资源；分组界面不展示这些任务专用操作，转回 Task 后继续使用原值。项目类型转换不属于本次能力。
- 折叠／展开按所有所选分支的完整子树执行，父子重复选择去重，只更新一次视图状态；即使右击的主项没有子任务，也会为选区中的其他分支提供这两个入口。

本次没有接入甘特／四象限／日历的统一多选，也没有新增批量状态、标签或移动方式；下文对应部分继续作为后续设计。导图与列表现有的完成、删除、挂载和样式能力仍需按本文规则逐步统一。

## 1. 推荐结论

时间与优先级都应支持批量设置，而且应当是多选后的直接入口。用户不需要先学会右键菜单，或切换到某个特定视图，才能给几项任务统一排期。

推荐先完成一条完整链路：**五视图都能方便地选中多项 → 看清选中范围 → 设置时间／优先级 → 一次应用 → 一次撤销**。随后把状态、标签、移动与删除纳入相同规则。标题、正文和任务关联资源不适合直接照搬成批量覆盖。

用户应该能轻便完成这些操作：

- 在导图框选三个具体任务，将优先级统一设为「重要」，再将截止日期改为本周五。
- 在列表选择多项任务，把原有排期整体顺延一天，保留各自的开始、截止和时分。
- 在日历选择几项任务，清除它们的任务排期，不删除任务，也不删除既有日程记录。

这里的「统一截止日期」「统一时间区间」和「原排期整体顺延」是三种不同意图，必须分别提供明确入口。

## 2. 实施前的代码快照

首次分析时是分散、不完整的多选能力，还没有形成跨视图、可发现、可靠的批量操作体验。下表和问题清单记录实施前的依据；已修复范围见上方「已实施的第一步」。

| 范围 | 已有能力 | 主要缺口 |
| --- | --- | --- |
| 导图 | 修饰键多选、空白框选、⌘／Ctrl + A；多选样式；右键菜单可携带多个 ID | 常驻选择条主要提供样式，时间与优先级藏在右键；没有完整的批量日期面板 |
| 列表 | ⌘／Ctrl 增减、Shift 连续选择；浮动条提供挂载、完成、删除；可把选区传入右键菜单 | 没有直接的批量时间与优先级入口；触屏难以持续选择 |
| 甘特图 | 单任务名称、进度条、排期拖动与右键操作 | 未形成多项选择、整批属性编辑链路 |
| 四象限 | 单任务详情、完成与象限拖动 | 未形成多项选择与批量设置 |
| 日历 | 单任务、关联日程及溢出列表操作 | 未形成基于 Task ID 的多项选择；同一任务可能在多个位置出现 |
| 共享层 | `TaskMenu.ids` 可传递多个目标；已有任务写入、样式事务和整批删除方法 | 没有跨视图统一的选择协议、字段适用性判断和批量执行入口 |

需要一并解决的具体问题：

1. `TaskMenu` 根据被右击主项的类型决定是否显示日期／优先级，而不是按整批对象判断。结构节点与普通任务混选时，不能保证菜单和实际写入范围一致。
2. 列表右键菜单只要存在多选就传入旧选区；导图右键会把主项与已有选区拼在一起。右击未选中任务可能作用到用户没有预期的另一批任务。
3. 右键日期的「自定义」目前打开一个任务的详情，不是批量日期编辑器；「已应用到 N 个任务」也不应在操作尚未提交时出现。
4. 日期、优先级、状态等操作分别循环调用单任务方法，事务、持久化反馈和撤销边界不一致。
5. `updateTask` 不会普遍拒绝结构节点的日期／优先级字段，不能仅依赖菜单隐藏保护数据。

源码核对入口：

- [ListView.tsx](../../apps/web/src/features/tasks/list/ListView.tsx)：选择、浮动条和右键选区。
- [MindMapView.tsx](../../apps/web/src/features/tasks/mindmap/MindMapView.tsx)：React Flow 选择与批量菜单。
- [TaskMenu.tsx](../../apps/web/src/shared/TaskMenu.tsx)：日期、优先级与批量目标。
- [ui.ts](../../apps/web/src/state/ui.ts)：单任务详情状态与菜单状态。
- [store.ts](../../packages/crdt/src/store.ts)：字段更新、完成时间、样式事务和子树删除。

上述是代码存在性的核对，不代表当前多选手感、可发现性和全部路径已经通过交互验收。

## 3. 哪些属性与方法应该支持批量

| 属性／操作 | 建议 | 作用范围与约束 |
| --- | --- | --- |
| 优先级 P0–P3 | **首期必做** | 统一赋值，仅普通任务；同步重要／紧急字段和四象限 |
| 开始日期、截止日期、明确时间 | **首期必做** | 每个字段独立保持／设置／清除；保留未修改的另一端 |
| 同一开始—截止区间 | **首期必做** | 用户明确选择「统一排期」后，同时设置两端 |
| 清除排期 | **首期必做** | 同时清除开始与截止；不清除完成时间或历史记录 |
| 整体顺延／提前 | **首期必做** | 同量移动各任务已有的日期端点；无日期项明确列为不适用 |
| 待办／进行中／已完成 | 应支持，随后接入 | 显式设为某状态，不对混合状态执行逐项反转；需先统一完成操作的日期副作用 |
| 标签 | 应支持，随后接入 | 提供添加、移除、清空；默认保留各任务原有的其他标签 |
| 移动到项目／父任务 | 应支持，随后接入 | 只移动选中森林的顶层项；保留父子关系与顺序，阻止循环 |
| 删除到回收站 | 应支持并统一现有能力 | 明确展示实际受影响的子树范围，去重后一次删除、一次撤销 |
| 恢复 | 后续，在回收站设计中接入 | 复用删除批次及必要祖先恢复规则，不恢复无关兄弟或更早删除项 |
| 导图样式 | 保留并统一入口 | 背景、文字色、字体、字号、粗体、斜体及恢复默认；普通任务和真实结构节点均可适用 |
| 预计耗时 `estimateMin` | 后续可支持 | 明确是「每项设为 X 分钟」，不能将总时长默认为各任务时长 |
| 归档／取消归档 | 后续单独定义 | 当前模型直接使用 `status=archived`，需先明确归档前状态及恢复语义 |
| 转为任务／分组 | **已支持** | 显式统一目标类型；项目不参与，原内容和层级保留，普通顶层分组不升级为项目 |
| 转为项目 | 不提供批量入口 | 涉及项目根身份与层级；保留原有单任务顶层转换入口 |
| 标题、描述正文 | 不提供通用批量覆盖 | 每项内容通常不同；将来如支持统一追加、替换，应独立设计预览和覆盖范围 |
| tmux、Agent、Note、PR、DSH 等关联资源 | 不纳入本次 | 内容和权限各有含义；尤其不能因批量选择就启动远端终端或 Agent |
| 专注、进入详情、跳转视图 | 保留单目标语义 | 多选不能隐式创建多个专注会话或打开一批页面；需要定位时由用户明确指定一个主项 |
| ID、账号归属、创建／修改／完成时间、排序数值 | 不提供原始批量字段编辑 | 身份与历史由领域操作维护；排序通过移动／排序交互表达 |

## 4. 统一的选择与入口

### 4.1 保留轻便的单项操作

普通浏览时，单击打开详情、双击编辑标题以及现有日期／排期操作保持各视图既定语义。多选不依赖用户先关闭「单击打开详情」偏好。

五个视图在工作区工具栏相同位置提供一个紧凑的「多选」入口。进入后，点击任务只切换选择，不弹详情；退出后恢复普通浏览。桌面修饰键与框选也可直接进入多选，不强迫先点按钮。

| 操作 | 规则 |
| --- | --- |
| ⌘／Ctrl + 点击 | 在当前选择中增减一项，不打开详情 |
| Shift + 点击 | 列表和甘特按当前展开行顺序选择连续区间；二维导图、四象限和日历沿用增减选择，不猜测二维区间 |
| 导图空白框选 | 继续支持；不抢占双指平移、不随框选打开详情 |
| ⌘／Ctrl + A | 工作区拥有焦点时选择当前可选项；输入框、描述、终端等保留自身全选行为 |
| 多选模式下点击任务 | 增减选择；完成图标与选择标记分开，不用“完成勾选”表达“选中” |
| 右击已选中的任务 | 保留选区，显示该批对象可用的批量操作 |
| 右击未选中的任务 | 切换为该项的单项菜单，不静默追加到旧选区，也不继续操作旧选区 |
| Esc／取消选择 | 弹层打开时先关闭弹层；随后退出多选并清空选择 |

触屏通过「多选」进入选择模式。长按可作为辅助入口，但不以长按为唯一方法，也不抢占系统文本选择。批量编辑用底部面板；操作区域保持可触达，不能借多选把完成按钮缩成难点的小图标。

### 4.2 看得见选择了什么

选择条直接提供：`已选 N 项 · 时间 · 优先级 · 更多 · 取消`。后续状态、标签、移动、删除放在「更多」，不把整套完整详情堆到工具条上。

点击「已选 N 项」可查看选中清单与所属项目。混选时显示类似「8 项任务、2 个分组」，日期面板进一步说明「将修改 8 项任务，2 个分组不适用」。如果全部不适用，对应入口禁用并说明原因。

选区和单项详情是不同概念。选中多项时不显示最后一项的完整详情冒充批量编辑器；多个值不同时显示「多个值」，不以空白或「未设置」替代。

### 4.3 全选、过滤和重复展示

- 默认全选限于当前账号、工作区、筛选和展开范围中的可选项；包含滚动区域外的逻辑行，不以 DOM 是否挂载决定目标。
- 折叠子树不默认整批选入；导图为理解全局而保留的弱化背景上下文，不随「全选当前筛选结果」自动加入。主动逐项选择的对象则应明确计入选中清单。
- 全图且无额外筛选时，真实项目／分组节点可以参与选择和样式修改；用户名虚拟根节点始终不进入批量数据目标。
- 日历「还有 X 项」和四象限展示限量后的条目属于当前结果，但不能让用户误以为只选了屏幕上的几项。全选按钮标明实际总数，选中清单可查看全部；日历单元格显示该日选中数量，四象限显示选中／总数。
- 同一 Task 在日历截止标记、关联时间块或溢出列表重复出现时，按 Task ID 去重并同步高亮，只计一次。独立日程不是 Task，不加入 Task 批量操作。
- 切换账号、项目、快捷视图、视图或用户主动修改筛选时结束当前选择会话；不保存到服务端或跨账号恢复。由批量修改本身造成的筛选变化，按第 7 节保留结果反馈。

### 4.4 与拖动的分工

首期多选模式优先保证「选择 → 设置属性」可靠。甘特条拖动、日历拖拽改期和四象限拖动改优先级继续保留在普通单项模式；多选模式下不出现视觉上移动一批、实际只保存主项的行为。

批量甘特拖动、导图整批挂载等可在后续接入同一执行规则。它们不是首期批量设置的前置条件，用户可先用「整体顺延」完成多任务改期。

## 5. 时间批量设置的具体含义

### 5.1 每个字段有三种意图

| 编辑意图 | 写入 |
| --- | --- |
| 不修改 | 不发送这个字段，逐项保留原值 |
| 设置 | 写入明确日期／时刻 |
| 清除 | 写入 `null` |

批量面板默认所有字段「不修改」。只改截止时间时，不重写开始时间；只改优先级时，不附带任何日期字段。输入框显示「多个值」只是摘要，不构成清空意图。

### 5.2 提供五种明确操作

| 操作 | 行为 |
| --- | --- |
| 设置截止 | 只改变 `dueAt`；另一端保持原值 |
| 设置开始 | 只改变 `startAt`；另一端保持原值 |
| 统一排期 | 明确同时填写开始与截止，为每项写入相同区间；会改变各自原有时长 |
| 清除排期 | 同时写入 `startAt=null`、`dueAt=null`，不改 `completedAt`、状态和历史记录 |
| 整体顺延／提前 | 各自已有的日期端点按相同本地日历天数移动；保留各自时分、端点缺失情况与相对安排 |

快捷项可以包括今天、明天、本周五、顺延一天和清除排期，但标签明确写「截止到今天」等，避免把它们与工作区时间筛选混为一谈。

只选择日期时，默认保留每项该端点原有时分；没有该端点时，建议开始补当天 00:00、截止补当天 23:59，并在面板中说明。显式选择统一时刻时，才统一时分。23:59 与现有日期快捷项保持一致；这是写入默认值，不宣称当前数据模型已有“全天任务”字段。

### 5.3 例子与边界

原来：A 为周一 09:00—周二 18:00，B 为仅周三 20:00 截止，C 完全未排期。

- 「整体顺延一天」：A 变为周二 09:00—周三 18:00；B 仍没有开始时间，截止改为周四 20:00；C 保持未排期。提交前显示「将顺延 2 项，1 项无排期不适用」。
- 「统一截止到周五」：A、B 的截止分别保留 18:00、20:00；C 新增周五 23:59 截止，开始仍为空。若勾选明确的统一时刻，则三项都使用那个时刻。
- 「统一排期周四 09:00—周五 18:00」：三项都写入这两端；这不是顺延，也不是保留原时长。

适用性和校验规则：

- 结构节点不参与日期修改；无排期项在整体移动时不适用，但可以参与设置开始、设置截止和统一排期。
- 校验每项的新截止不早于新开始。只改截止会与某项原有开始冲突时，列出冲突对象并阻止整批提交，不能偷偷把另一端也改掉，或临时跳过冲突项后声称全部成功。
- 必要时让用户显式从这次操作排除冲突对象，再生成新的修改预览；不自动改写选择范围。
- 用用户本地时区做日期运算，再转换为 UTC 毫秒。按天顺延不是无条件加 `24×60×60×1000`；跨月、跨年及夏令时需要正确处理。夏令时缺失的本地时刻应提示调整，不能无声漂移。
- 修改已完成任务的排期不把它改为待办，不重写实际完成时间。优先级条色保持既有语义，日期改动只更新相应时间／状态提示。
- 日期只改 Task 的排期，不自动移动关联日程、专注历史或资源记录。某项仍因关联日程出现在本周日历时，应区分任务排期与关联日程，不能用父节点或旧显示缓存伪造任务日期。

## 6. 其他批量操作的语义

### 优先级

直接设为 P0／P1／P2／P3；「恢复普通」对应 P3。只更新选中的普通任务，不因选中父任务就修改其未选中的子任务。派生的重要／紧急和四象限必须同时一致，不能出现两套优先级互相冲突。

混合优先级显示「多个值」，不预先选中主项的值。已经符合目标值的任务按无变化处理，不刷新其修改时间或额外制造撤销记录。

### 状态

提供「设为待办／设为进行中／设为已完成」，不使用“将各自状态反转”的批量开关。已完成项再次设为完成时保留原完成时间；结构节点不参与。

当前 `setTaskStatus` 会在无截止时补写完成时刻为截止。接入批量完成前，应把这一行为作为单项与批量共用的规则明确下来；推荐排期和实际完成分离，完成只维护状态与 `completedAt`。这涉及既有单项行为，放入后续阶段一并调整，不能在批量方法中另造一套隐蔽语义。

### 标签

支持「添加某标签」「移除某标签」「清空标签」。添加做集合并集，移除只删除指定标签，不覆盖其他标签。标签汇总区区分全部共有与部分拥有。

首版标签批量操作使用已有标签。创建标签是独立动作，随后再附加到选区，避免把标签字典和任务关联跨文档变更伪装成天然的一次原子事务。

### 移动与层级

父 P 与其子 C 同时选中，移到项目 X 时只移动 P，C 仍在 P 下；不把两项摊平成 X 下的两个兄弟。按当前稳定的选区顺序移动各顶层分支，保留分支内部顺序。

不能移动到自身、所选后代或已删除目标，也不能把真实项目根作为普通子任务移动。提交前校验全部可移动分支，避免一半移动后才发现循环。首期不根据拖动方向推测复杂整批重组意图。

### 删除、恢复与折叠

删除按合并后的子树执行；父子同时选中只计算一次，同一次删除使用统一批次。确认中展示「选中 3 项，实际影响 12 项，含 9 项未直接选中的后代」，而不是只显示选择数。删除已有确认后不叠加第二次确认，完成后提供撤销与回收站入口。

恢复仅恢复相应批次和必要祖先，不顺带恢复更早独立删除的任务。折叠／展开本身属于视图操作，可批量作用于所选分支，但不改变任务内容，也不自动扩大业务字段修改范围。

## 7. 提交、撤销与同步

推荐两个层次：先计算修改计划，再提交，所有视图共用它们。

1. **选择与适用性**：按 ID 去重，记录当前账号、工作区和选区。按操作筛选普通任务／结构节点／其他对象，明确显示不适用原因；不能仅看右击主项。
2. **生成预览**：读取最新任务，计算每项必要字段的前后差异。没有变化的项目不参与写入；日期非法、目标无效等校验在任何变更前完成。
3. **提交前复核**：检查相关原值及层级是否在弹层打开期间变化。无关字段更新可保留；同一待改字段、删除状态或子树范围变化时刷新预览并说明，不悄悄覆盖另一个设备的新内容。
4. **整批写入**：任务数据使用一个 Yjs 事务和一个撤销单元，只写变化字段。事务前后明确划分撤销捕获，不能依赖“循环很快，所以刚好合成一次”。Yjs 事务不提供异常自动回滚，因此必须先校验完再开始写。
5. **完成反馈**：应用后即时更新视图，反馈「已更新 N 项 · 撤销」。普通优先级和简单日期快捷操作不再弹第二个确认框；自定义面板只有一次明确的「应用」提交，取消和点外部不落库。

持久化失败时，若内存已经应用变更，应如实提示「更改已应用，本地保存失败」，保留页面、选区和恢复入口，不能把它误报成完全没执行并重新重放一次。离线状态说明本地保存与待同步状态，不声称服务器已经确认。

批量操作执行期间固定本次目标集合，防止筛选响应式更新导致循环中途少改或多改。提交后的单次渲染再调整选择：仍在当前范围的项保留，移出范围的项清除选择，并提示「已更新 8 项，3 项因当前筛选已移出」。清除选择本身不撤销已提交修改。

Undo 只撤销这次本地操作涉及的字段，按现有 CRDT 合并规则保留其他设备无关编辑；不得用整项旧快照回滚。对同字段并发不能承诺跨设备的全局事务隔离，验收需覆盖实际 Yjs 行为，避免误导用户。

## 8. 实施顺序与代码方向

### 首期：把时间与优先级的整条链路做完整

- 五个视图全部接入统一多选入口、选择数量、可查看的清单和选择条；触屏可进入选择模式。
- 日期支持独立设置、明确区间、清除、按天整体移动；优先级支持 P0–P3，直接可达。
- 支持混合值、对象类型适用性、整批校验、一次应用／一次撤销，以及筛选移出后的反馈。
- 修正右键选区范围、快捷键焦点和与单项详情的冲突。已有批量删除、挂载和样式暂保留能力，但必须服从新的选区边界，不在菜单中继续执行类型不明确的整批转换。

### 随后：接入更多高频操作

在同一执行链路上加入状态、标签、移动、删除及视图折叠；同步清理完成时间与排期的历史副作用。集中验证父子同时选中、子树删除与恢复、跨项目移动和相关撤销。

### 后续：按实际需要扩展

评估整批甘特拖动、选择完整分支、归档／恢复状态、预计耗时，以及 Agent 端批量端点。原生批量 REST 接口应单独设计权限、幂等、版本冲突、大小限制和原子性；当前逐项 REST 请求没有整批事务，不能提前在 API 文档或 Skill 中声称已经具备。

实现建议：

- 选择会话置于工作区作用域，单项详情 ID 与批量选择分离。每个视图提供同一套选择动作和可选项集合；不把 DOM 节点引用、任务完整快照或选择状态持久化到业务文档。
- 导图的 React Flow 选中标志与工作区选择集合必须明确唯一真源及适配方式。不能用两组互相监听的 effect 反复同步，重演选择回声、重排覆盖和连接线消失问题。
- 在 core／CRDT 层集中生成与应用批量任务变更，复用 `setTaskPriority` 的领域规则、`softDeleteTasks` 的统一删除批次及 `setMindAppearance` 的事务方式；不让五个视图各写一份 `ids.forEach(updateTask)`。
- 批量时间面板与单项日期控件共享日期解析和显示规则，保留各自的交互容器。日期面板显示操作含义，不把内部字段名和事务实现塞给产品用户。
- 图节点的选择变化只改变必要的选择标志和样式，普通选择／优先级更新不重新测量整张导图，不重置画布视角；批量标题／样式等真实尺寸变化再按需处理布局。

## 9. 验收标准

| 场景 | 预期 |
| --- | --- |
| 五视图各选三项，设置重要优先级 | 三项实际数据一致，其他任务不变，其他视图与四象限同步反映 |
| 优先级与时间均不同的混合选择 | 显示「多个值」；只修改用户动过的字段 |
| 两项任务加一个分组 | 日期／优先级明确只影响两项；样式可作用于三项；分组不出现排期字段污染 |
| 父 P 与子 C 同时选中设优先级 | P、C 各处理一次；未选中的兄弟和后代不变 |
| 父 P 与子 C 同时移动／删除 | 移动保留层级；删除合并子树、计数准确、批次统一 |
| 只改截止导致一项开始晚于截止 | 整批阻止提交，指出冲突项；另一端不自动跳动 |
| 单端排期、无排期与已完成混选后顺延 | 缺失端点仍缺失，无排期不补日期，已完成项完成时间不变 |
| 跨周、跨月、跨年和夏令时移动 | 本地日期与时分按约定保持；不存在的本地时刻有明确处理 |
| 清除排期 | 两端均为空；不会因父节点、缓存或视图默认值再次显示虚假任务排期 |
| 日历同一 Task 出现多次 | 选中数量、写入次数和撤销都按 Task ID 去重；独立日程不被改动 |
| 日历溢出、矩阵限量、长列表虚拟化 | 全选范围和总数可核实；不漏掉逻辑结果，也不偷偷包含折叠子树或背景上下文 |
| 多选后右击未选中项 | 菜单只针对该项；不会修改旧选择集 |
| 输入标题、备注或终端时按全选／删除 | 按控件本身语义工作，不触发批量任务动作 |
| 一次应用后撤销／重做、刷新、同步另一设备 | 字段恢复与持久化正确，其他任务与无关编辑保留 |
| 操作造成任务移出筛选 | 目标集合不在循环途中改变，提交结果与移出数量可见 |
| 面板期间远端编辑／删除、离线或保存失败 | 不写过期对象或覆盖无关字段，不把部分已应用结果误报为全未执行 |
| 320／390 px 触屏选择，桌面 200／1000 项选区 | 批量条可操作，不反复弹详情、不冻结输入；选择不造成全图反复测量 |

回归在独立临时实例与模拟数据上进行，不在生产账号中批量改日期、设优先级或删除任务。首期完成后再将已实现部分同步回整体交互文档、移动端文档和操作说明。
