## 1. 设计目标与 T3 Code 参考

目标体验：用户从 Task 打开 Agent 后，立刻能读到连续工作内容、辨认当前进度和需回应事项，并在不丢失上下文的情况下打开终端、检查变更、查看 Task 或继续发送指令。

对齐 T3 Code 的空间组织、密度、组件一致性、内容层级和交互反馈。范围以 Agent 工作台为重点，并覆盖全站外壳、公共控件和配置页面，避免只换聊天面板却留下两套设计语言。同时保留 Nexus 的项目树、五种任务视图、习惯、复盘、Task 正文及业务验收。T3 的 Project／Thread 不直接替换 Nexus 的 Task／Workspace。

## 2. 信息架构与入口

### 2.1 保留任务工作区，建立独立 Agent 工作台

- 侧栏继续保留当前工作、本周工作快捷视图、项目、快捷视图、习惯／复盘等入口。
- “当前工作”表示 Agent 等待回应、待验收、执行中和异常的工作；“本周工作”仍是按时间筛选的任务视图，不与 Agent 状态混合。
- `/work` 保留按 Task 聚合的四区看板（等我回复／待验收／执行中／异常），同一任务的多个 Agent 放在同一卡片内。总览沿用项目、快捷视图和工具侧栏；只有 `/work/agents/:agentId` 具体会话切换为 Agent 侧栏。不能把总览替换成全部 Agent 的平铺列表。
- 看板任务标题和会话顶栏均提供“打开 Task”：进入所属项目记住的视图并定位任务，展开祖先，显式定位不受默认本周范围阻挡。从看板进入会话时，返回箭头回到看板；从任务进入时保留原任务视图返回位置。
- Task 详情中的 Agent 行点击后打开独立工作台，返回后恢复原视图、节点选择、镜头／滚动及筛选。
- 全局新建 Agent 必须选择主要 Task；从 Task 发起则已选好，不重复询问。
- Workspace 管理可从设置、当前工作菜单及 Task 的 Workspace 区进入；不把模板管理放到 Agent 列表最后导致难以发现。

建议新增可深链路由 `/work/agents/:agentId`；现有 `/work` 保留为工作收件箱。路由在实现时统一与现有导航兼容，本文路径不代表现有公开端点。

### 2.2 一条主要左侧栏

宽屏不长期同时展示“全局侧栏 + 大型 Agent 列表 + 对话 + 详情”四列。在 Agent 工作台中，复用左侧栏的上下文区域展示 Agent 列表，提供“项目 / Agent”切换；全局入口和底部账号行保持稳定。切回任务视图恢复项目导航状态。

Agent 列表可按项目筛选，默认分组为“等我回应”“待验收”“执行中”“异常”“最近”，空组隐藏。折叠状态与筛选按账号／设备记忆。收到 token 不重新排列列表；只有业务状态改变才进入对应组，正在键盘操作的行不突然移位。

每行主标题优先 Task 标题，次行只在需要区分时显示 Agent 名、项目或 Workspace；同一 Task 多 Agent 必须显示名称。右侧使用小状态图标和相对时间。菜单按钮在 hover／focus 时出现，触屏可直接访问；整行选中背景包含菜单和拖动区域。

底部维持“设置 · 用户名 · 同步状态”一行，设置页直接展示可切换账号。切换账号不影响后台工作，但立即清除旧账号可见对话、草稿引用、终端和订阅。

## 3. 桌面布局与响应式

### 3.1 标准工作台

```text
┌──────────────────┬──────────────────────────────────────────────────────────┐
│ 当前工作   本周工作│ 项目 / Task                         执行中   终端  详情 ⋯ │
│ 项目 | Agent      ├──────────────────────────────────────────────────────────┤
│ 搜索 Agent…       │                 对话阅读列                              │
│                  │                                  用户输入浅底块         │
│ 等我回应       2  │ Agent 回复正文                                          │
│   登录优化       │ ▸ 读取 4 个文件                                         │
│   实验设计       │ ▸ 运行测试 · 已通过                                     │
│ 执行中         1  │                                                         │
│ ▌日历优化        │ [修改 3 个文件]  [PR #128]                              │
│ 最近             │                                                         │
│   数据导出       │ ┌ 需要你确认：允许执行这条命令？ ── 允许一次  拒绝 ┐    │
│                  │ ├ 输入消息／补充要求…                              ┤    │
│                  │ │ ＋  Codex · 模型   需审批              排队发送 ↑│    │
│ 设置 · 用户 · 同步│ └─────────────────────────────────────────────────┘    │
└──────────────────┴──────────────────────────────────────────────────────────┘
```

对话默认占据主工作区。顶栏只保留当前 Task 路径、主状态、终端、详情及更多；Provider、模型和发送策略在输入器下方，避免顶部重复一整套配置。

Agent 名与 Task 不同时，在标题附近显示紧凑副标题。完整 Workspace 名、路径、分支可从上下文条展开，不用多行常驻小字挤压正文。

### 3.2 辅助面板

右侧详情面板默认关闭，内含“Task / 变更 / Workspace”标签页。只展示当前 Agent 的信息，切换会话更新内容；用户正在编辑未保存内容时先按已有保存语义落盘或保留草稿，不默默丢失。

对话与终端共享同一主区域，通过顶栏切换。查看原终端时替换对话区，不上下分屏，也不并排挤压对话。切回对话保留草稿、问题选择与阅读位置；关闭终端只 detach。仍支持单独全屏。下图为对话与详情布局示意；终端打开时替换整个主区域，详情暂时隐藏。

```text
┌───────────────┬───────────────────────────────┬───────────────────┐
│ Agent 列表    │ Task 标题            终端 详情│ Task | 变更 | WS  │
│               │                               │                   │
│               │ 对话                          │ 文件列表／Diff    │
│               │                               │ 或任务正文        │
│               │ 审批 / 输入器                 │                   │
└───────────────┴───────────────────────────────┴───────────────────┘
```

### 3.3 几何规范

以下是 Nexus 建议值；T3 的参考事实仅以第 1 节为准。

| 项目 | 目标值／行为 |
| --- | --- |
| 顶栏 | 52 px，按钮与标题垂直居中 |
| 侧栏 | 默认 256 px，最小 208 px，最大 360 px，并保证主区最低可用宽度 |
| 对话列 | 默认最大 736 px（46 rem）；可选宽模式 960 px，大 Diff 可打开扩展面板 |
| 主区边距 | 桌面 20–24 px，窄屏 12–16 px |
| 右侧面板 | 默认 360 px，可调 300–480 px；可用空间不足转覆盖抽屉 |
| 终端 | 替换整个对话主区域，隐藏输入器与详情侧栏；保留顶栏切回对话，支持全屏 |
| Agent 行 | 单行约 36 px，需副标题时 48–52 px，不固定把所有行做成大卡片 |
| 控件 | 默认 32 px，小图标按钮 28 px，触屏命中区域至少 44 px |
| 输入器 | 最低约 96 px，随输入增长，最高主区可用高度的 35% 后内部滚动 |

宽度以实际容器判断。主对话低于约 560 px 时先折叠辅助面板；低于约 960 px 的视口默认覆盖式侧栏，低于 768 px 使用单面布局。用户调整尺寸按账号、设备、面板类型记忆，不让某个极窄窗口永久压坏其他设备布局。

移动端只有一个活动主表面：对话、终端或详情，明确返回路径；输入器随可视视口和键盘调整，尊重 safe-area。终端沿用顶栏下主区域，也可主动全屏，关闭只是 detach。移动输入字号至少 16 px，避免 iOS 自动放大。

## 4. 视觉语言与组件规范

### 4.1 字体、色彩、边界

Agent 界面采用 T3 风格的中性表面、克制描边和清晰文字层级。全局布局不铺彩色渐变，不给每个工具／状态都加大面积底色。

| Token | 浅色建议 | 深色建议 |
| --- | --- | --- |
| `agent.canvas` | `#ffffff` | `#191b1f` |
| `agent.sidebar` | `#f7f7f8` | `#15171a` |
| `agent.surface` | `#f2f3f5` | `#24272c` |
| `agent.foreground` | `#272a30` | `#e7e9ed` |
| `agent.muted` | `#626975` | `#a2a9b4` |
| `agent.border` | `#e5e7eb` | `#343840` |
| `agent.hover` | `#f1f2f4` | `#262a30` |
| `agent.selected` | `#e9edf2` | `#303640` |
| `agent.focus` | 使用用户强调色 | 使用用户强调色的可辨识变体 |

这些颜色是待浏览器验收的初值，不宣称已通过全部对比度检测。正文对比度至少 4.5:1，重要控件边界与焦点至少 3:1；选中和状态同时有形状、图标或文字，不能只靠颜色。

字体按区域定义：Agent 导航／控件默认 system sans，正文 15–16 px、行高 1.6，辅助信息 12–13 px；代码与终端使用等宽字体 13–14 px。标题与按钮仅局部 medium／semibold，不整页加粗。保留用户显式字体偏好；导图继续使用既有霞鹜文楷 16 px 加粗，节点自定义样式不被本次 UI 对齐重置。

图标统一 Lucide 体系，常规 16 px、笔画约 1.5–1.75；小图标 14 px，触控区域与视觉图标尺寸分开。表面以留白和细边界区分，普通面板无重阴影；输入器可用轻阴影，弹层才使用明确浮层阴影。基础控件圆角 8 px、输入器约 12–16 px，避免每个元素都变成胶囊。

### 4.2 一套公共控件

公共组件提供 `size`、`variant`、`density` 和 `state`；功能页只控制布局，不覆盖控件内部颜色、箭头位置或圆角。菜单、Select、Popover、Tooltip、Sheet 的间距和焦点规则统一。

下拉右侧至少保留 28–32 px 图标区，箭头距边约 10 px；长值省略但可以查看完整内容。列表项选中标记固定占位，不因勾选而移动文字。危险操作进入菜单或确认弹层，不能与发送按钮同等突出。

hover／pressed 只改变表面和边界，不改 padding、字号或外框几何。焦点环不引发布局位移；按钮点击即时反馈，不等待远端操作后才改变外观。动画优先 opacity，约 100–160 ms，遵守 reduced-motion，不用持续呼吸／闪烁表达所有运行状态。

### 4.3 全站如何保持一致

Agent token 在落地时映射到现有语义主题，并逐步由公共控件承载，不能永久维护两套外观不同的 Button／Select／Sheet。画布专用颜色和节点自定义样式仍单独管理。

| 页面／区域 | 对齐内容 | 保留的产品行为 |
| --- | --- | --- |
| 全局侧栏与顶栏 | 相同高度、行密度、图标、选中表面、悬浮菜单和缩放规则 | 项目／快捷视图折叠、拖动排序、宽度记忆、底部账号行 |
| Task 列表与详情 | 统一行高层级、工具栏、Popover、字段和详情面板外壳 | 紧凑编辑、日期／优先级同一行、自动保存、正文版本 |
| 导图 | 浮动工具栏、菜单、提示和配置面板使用公共控件 | 霞鹜文楷、16 px 加粗、画布位置、节点样式、连线与框选语义 |
| 甘特／日历／四象限 | 同一视图切换和筛选工具栏，统一任务浮层和状态颜色语义 | 每项目视图记忆、日期拖动、日历溢出、批量操作 |
| 习惯与复盘 | 相同标题、表单、折叠行、保存状态和空态 | 习惯一行一个、打卡热图、次数进度、多提醒、日报／周报正文 |
| 设置／服务器／集群 | 克制的分组表单、紧凑连接行、统一验证和操作反馈 | 账号直接可切换，SSH 与 Kubernetes 凭据仍按账号管理 |
| Workspace／Provider | 模板与实例页面使用相同列表和编辑器外壳 | 能力检测、配置来源、资源生命周期和凭据边界 |

不为了视觉对齐重置用户主题、字体、日期、过滤器或任务数据。迁移先定义共享 token 和控件变体，再逐页替换；每页交付必须同时验证浅深主题与现有交互。

## 5. 对话、工具与产物

### 5.1 消息时间线

- 用户输入使用右侧浅底容器，最大阅读列的约 80–85%；Agent 回复左对齐，正文为主，避免连续头像和大标题重复。
- 相邻消息由稳定 messageId 区分；工具或审批更新原卡片，不能每次增量新增一整张。
- 用户消息立即进入“发送中／排队”状态，确认接收后更新；投递未知显示“待核对”，不给一键无条件重发。
- 时间、复制、定位到该轮等操作在 hover／focus 显示；触屏从行菜单访问。
- 长用户消息、工具输出和已完成计划可折叠；最终回复与当前待回应问题默认展开。
- 只呈现 Provider 明确提供的思考摘要／进展，不承诺展示模型完整内部推理。
- Round 用轻量分隔行和结果卡表达，不为每轮强制插入多段空模板。

### 5.2 工具活动

工具默认一行：状态图标、动作名、目标、耗时或结果，例如“读取 4 个文件”“运行 pnpm test · 通过”。相邻同类且已完成的活动可以汇总，展开能看到每个真实调用。正在运行、失败、需审批的调用不能被汇总隐藏。

展开后显示命令／参数、目录、输出、退出状态或文件 Diff。大输出分页／截断并提供完整日志入口，避免把万行构建输出直接插入主时间线。日志保留可复制文本，默认不自动折叠用户正在选择的内容。

### 5.3 变更与交付

对话末尾的产物使用紧凑链接／卡片：修改文件数、提交、PR、设计文档、验证结果。点击文件打开右侧变更面板；桌面 Diff 支持并排／统一格式，窄屏使用统一格式。缺少原生 Diff 能力时可从 Workspace Git 状态读取，但须标明来源和刷新时间，不把其他 WorkArea 的修改混入。

报告展示“做了什么、如何验证、尚未完成什么、产物”。以自由对话为主，不常驻“验收本轮／开始新一轮／提出调整”流程按钮；用户直接回复即可继续，旧的已结束轮次自动建立后续记录。历史报告保留，整个 Task 的完成沿用任务入口。PR 按真实状态显示，不把 URL 存在当成已创建或已合并。

正文写回与报告保存分开显示；正文发生版本冲突时保留报告和拟写回内容，并提供查看差异／重新合并，不显示虚假的“已同步”。

## 6. 输入器、审批与问题

### 6.1 输入器布局

```text
┌ 上下文：当前 Task   + 添加引用                       ┐
│ 补充要求，或告诉 Agent 下一步做什么…                 │
│                                                     │
├ ＋   Codex · 模型 ▾   需审批 ▾      队列 1    发送 ↑ ┤
└─────────────────────────────────────────────────────┘
```

Provider 和模型值来自真实可用能力；切换产品会创建后继会话时先清楚说明，不悄悄丢失原生上下文。权限选项只展示后端可落实的策略，不能通过自动点击“允许”伪造沙箱能力。

Workspace／完整目录信息由一行上下文摘要打开，避免常驻路径占两三行。Prompt 模板只在新建／明确编辑时展开，普通发送不再展示创建配置。

桌面 Enter 发送、Shift+Enter 换行，尊重用户已有快捷键偏好；IME composition 期间 Enter 只确认候选，任何 keyCode=229／isComposing 场景都不能发送。移动端默认回车换行，独立发送按钮。切换 Agent 保留按账号＋Agent 的草稿，账号切换后不可见另一账号草稿。

执行中默认按钮为“排队发送”；支持原生 steering 时通过明确动作“追加到当前执行”调用。队列条可查看、编辑、取消未投递项。停止按钮仅在执行中显示，取消确认后再更新状态，不让点击本身伪装远端已停。

附件入口按能力显示；不支持附件／图片的 Harness 不出现可成功上传的假入口。基础文本、任务引用、文件引用先实现，语音、斜杠命令和复杂多模态可以后续扩展。

### 6.2 审批和用户问题

待处理项在原始时间线位置保留卡片，并在输入器上方提供一个固定处理入口；两者绑定同一请求 ID，处理后同时更新。多个请求显示数量和可切换列表，不弹一串模态框。

审批显示请求原因、具体命令／文件目标、工作目录及允许范围。按钮对应原生选项，至少可以拒绝；不默认预选允许。回答后显示“已回答”，等待 Provider 回执；过期或来自旧会话代次时标记失效，不能提交给新执行。

用户问题支持选项、自由文本和按协议允许的跳过；收起卡片不等于拒绝／确认。查看另一 Task、切换账号、刷新或关闭面板都不应自动批准。

### 6.3 阅读与滚动

位于底部时跟随新消息；用户上滚后保持锚点，显示“有新内容 ↓”。补发历史或工具卡片高度变化不得把用户拉回底部。重开会话恢复该账号的阅读位置；明确“查看最新”才跳到尾部。

文字选择、复制、Markdown 渲染和输入器编辑不被 token 更新打断。需要显示错误时靠近相关操作，不替换整段对话。首次读取只显示局部骨架，已有缓存先显示并标明同步状态。

## 7. Task、Workspace 与创建界面

### 7.1 Task 详情中的入口

保留现有 Task 标题、日期／优先级同一行、自由正文与历史版本。执行区域顺序如下：

```text
Workspace                         创建模板   创建 Workspace
  ▸ 可用模板 · 继承自 Serve
  nexus-dev        SSH · user@host       查看配置  ⋯
  gpu-test         Pod · namespace       查看配置  ⋯

Agents                                         创建 Agent
  Codex · 日历修复             执行中               →
  Claude · 方案审阅            等我回应             →
```

没有实例时只显示“暂无 Workspace”；创建和管理入口仍可见。模板列表默认收起，展开可查看、编辑、删除当前及祖先可用模板并标来源。实例可以展开查看配置快照及生命周期；用户无需进入另一个全局页面才能管理模板。

不恢复“设为默认”独立开关，不展示重复教学小字。当前查看实例只影响本次创建推荐。Agent 行进入主工作台，Task 详情不默认嵌入窄 tmux 或完整创建表单。

### 7.2 创建 Agent

采用一个中等宽度可滚动 Dialog／Sheet，桌面建议 640–720 px，固定标题和底部操作。按“Workspace → 工作目录 → Agent → 初始指令”排列，默认配置足够时直接创建。

```text
创建 Agent                                      ×
Task：Serve / 日历优化

Workspace
[ 使用已有 Workspace ] [ 创建新 Workspace ]
[ nexus-dev · SSH · 可用                         ▾ ]

工作目录
(●) 自动创建 Git worktree    ( ) 使用已有目录
名称  calendar-fix-a7c2                          编辑
路径：/home/user/…/nexus-agent/calendar-fix-a7c2
分支：nexus-agent/calendar-fix-a7c2

Agent
[ Codex ▾ ] [ 账号／配置 ▾ ] [ 模型 ▾ ]

▸ 初始指令                                      编辑
▸ 高级设置：终端、权限策略

                                  取消   创建并启动
```

两种 Workspace 来源使用标签页，切换保留草稿。当前已有合适实例时默认已有；没有合适实例时默认新建并推荐继承模板。用户手动选了空的已有列表时显示可切换空态，提交不能暗中改成新建。

工作目录选项互斥。worktree 名称可编辑但默认唯一，路径只读预览，读取中明确显示“正在解析路径”；未取得真实值前不用占位路径冒充最终路径。

| 选择 | 初始内容 | Git 分支 |
| --- | --- | --- |
| 自动创建 Git worktree | 从 Workspace 仓库检出代码，共享 Git 历史 | 新建 `nexus-agent/<名称>` |
| 创建空目录（不含仓库） | 空的专用文件夹，带归属标记，不复制仓库 | 不创建 |
| 使用自定义工作目录 | 直接使用该路径已有内容，同路径会共享修改 | 沿用 |

非 Git 项目默认空目录，禁用 worktree；空目录与 worktree 的名称都校验路径安全性。两者使用相同的管理路径形式，并不代表初始内容相同；worktree 也不等于 OS 安全沙箱。

默认 Prompt 只在读取上下文的步骤列出正文、祖先、资源和消息；信息不足时先提问的规则只说明一次。原生问答与 REST `questions`／`suggestions` 格式放在上下文 `interactionGuide`，不重复插入默认 Prompt，不向 Agent 解释 UI 的轮次按钮。

服务器设置可开关 Agent 代理、编辑代理地址及不经过代理的地址。按账号和服务器连接保存，仅对该连接下新启动的 SSH／独立用户 Agent 生效；不能把主机 loopback 代理无条件传进容器／Pod。诊断日志清理 ANSI 控制字符，模型列表超时有可展开的中文说明，不能仅凭 stderr 将正常会话标为失败。

“创建新 Workspace”显示模板、实例名及配置摘要，执行身份默认“使用配置用户”，独立用户放高级设置。复用实例时不显示可编辑身份。用户需要改身份、镜像或仓库基础时，引导创建新实例。

初始指令默认由 Task 生成，可展开完整查看编辑，不提供“澄清／设计／探索／实现／交付”阶段单选。终端默认“首次打开时创建”，高级设置可勾选同步创建。

校验错误紧贴字段，提交按钮说明阻塞原因；后端准备进度进入工作台，不让创建 Dialog 无期限转圈。再次点击／网络重试使用同一请求 ID，不创建第二个环境或工作树。

### 7.3 连续对话、建议和澄清

- 用户自由输入始终是主入口，不要求先选择工作阶段。已结束业务轮次的下一条普通消息会自动建立后续记录；不会自动标记 Task 完成，也不会自动验收报告。
- 默认 Prompt 和上下文 `interactionGuide` 要求先阅读 Task 正文、祖先背景、资源及消息。只有标题不足以判断目标时，第一轮先问 1–3 个影响推进的关键问题。
- Codex／Claude 的原生问题和 REST `waiting + questions` 都渲染为选择题。每个选项显示说明，支持单选、多选与自定义文本，不预选答案、不自动提交。原生问题走协议答复；REST 问题通过消息与上下文回传答案。
- 下一步建议由当前执行 Agent 通过进展事件或报告的 `suggestions` 上报，最多 4 项。只使用最近用户消息之后的建议；没有建议时显示发布、部署、总结进展等快捷消息。点击仅填入或追加草稿，聚焦输入框，用户编辑并发送后才执行。
- 不新增独立个人模型配置。建议没有执行权限，也不因出现“发布／部署”就启动操作。工具审批仍是独立的授权行为。

### 7.4 创建 Workspace／模板

模板表单将远程仓库、本地路径、来源策略、基准分支、PR 目标放在同一区块。PR 目标默认跟随基准分支，仅显示“跟随基准分支”按钮，不附加常驻解释。持久根目录有默认值，点击编辑图标才进入输入。

后端选择“SSH 主机 / Docker / Kubernetes”；身份为相关高级字段。模板不出现 tmux 会话选择、不出现固定 Agent 分支、不放 Prompt。

创建 Workspace 默认勾选“同时创建并启动 Agent”，勾选时显示精简 Agent 配置；取消后不启动 Agent。创建完成进入 Workspace 详情或实际 Agent 工作台，不自动向终端发送未确认的其他指令。

### 7.5 Workspace 管理

实例列表使用紧凑行，按名称、状态、位置、仓库和活动 Agent 数展示。展开详情显示配置快照、关联 Task、工作目录、终端和资源；模板更新与实例差异可查看，但不在每行显示长说明。

暂停、归档、解除关联、销毁实例、删除数据使用准确动词。销毁确认列出影响的 Task／Agent、未提交内容和资源范围，不能只显示泛化的“确定吗”。活跃执行无法安全停止时不让界面显示已销毁。

## 8. 终端、CLI 和控制权交接

“终端”是顶栏功能，不是 Agent 创建模式。打开进入当前 Agent 的 WorkArea；多终端标签位于终端区域顶端，路径可复制。未创建时用局部准备状态，失败后仍能阅读对话。

| UI 动作 | 用户可见反馈 |
| --- | --- |
| 关闭终端 | 面板收起，会话保留；无额外停止确认 |
| 结束终端会话 | 独立菜单动作，提示会终止该 Shell 中的程序 |
| Agent 正在运行时打开 | 标明共享目录，提供“暂停并接手修改”，不强迫只读查看也停 Agent |
| 申请接手 | 等待真实取消／暂停结果，再显示人工接手；失败保持原状态 |
| 在原生 CLI 中继续 | 仅支持时出现；说明会交接同一会话还是创建后继会话 |
| 从 CLI 返回 | 同步历史后恢复；无法恢复的差异明确提示，不复制终端屏幕伪装回复 |
| SSH 短暂中断 | 保留终端画面，显示重连状态，只重连原会话 |

终端获得焦点后，Ctrl+C、Esc、方向键等交给终端；全局快捷键不得劫持常用 Shell／TUI 操作。关闭入口始终可通过按钮访问；跨区域焦点移动有可发现的键盘入口。终端展开状态按 Agent 记忆，但刷新自动重连不发送键盘输入。

旧 tmux Agent 显示“终端接入”标签，可查看原 TUI 和工作记录；提供显式“创建结构化会话”迁移入口，不直接改变正在运行的进程。

## 9. 状态、错误与空态

| 场景 | 主展示 | 操作 |
| --- | --- | --- |
| 尚无 Agent | 简洁说明与“从 Task 创建 Agent” | 选择 Task／返回任务 |
| 环境／目录准备 | 当前真实阶段，已完成步骤可展开 | 失败后重试对应步骤 |
| 会话启动 | 启动产品名称，等待握手 | 查看启动日志、取消 |
| 执行中 | 一处主状态和实际最新活动 | 排队发送、受支持的追加、停止 |
| 等待审批／用户回答 | 侧栏标记＋输入器上方请求卡 | 回答、拒绝或按协议跳过 |
| 已有交付 | 报告与产物 | 直接回复，或选择 Agent 给出的下一步消息建议 |
| 会话空闲 | 可继续输入 | 继续当前会话，不重新创建目录 |
| 连接恢复中 | 保留已有内容＋小型连接提示 | 等待、检查连接，不默认“重发” |
| 投递结果未知 | 明确标识对应消息 | 核对远端结果，再决定新发送 |
| Provider 未安装／未登录 | 具体产品和目标环境 | 前往配置或终端完成安装／登录 |
| 凭据失效 | 区分 Nexus 执行凭据与模型登录 | 恢复对应凭据，不要求无关的浏览器重新登录 |
| 权限不足 | 保留允许查看的内容 | 提示所需权限，不展示可成功执行的控制按钮 |
| 离线 | 历史和本地草稿可读写 | 启动、审批、销毁不离线自动排队 |

错误尽可能定位到消息、工具、环境或连接，不用一个全屏错误覆盖所有历史。重要后台状态按需通知；没有用户授权不发送系统通知，也不以每个 token 触发通知。

## 10. 性能、无障碍与状态记忆

这些是待实现的验收预算，不能写成已经测得的现状。

- 本地点击、选择、菜单和发送草稿的视觉响应目标为 p95 小于 100 ms；网络操作单独显示状态，不把网络耗时混成本地交互延迟。
- 流式输出按消息项订阅，约 30–50 ms 合并更新，结束立即 flush；不能每个 token 重新渲染侧栏、全部 Markdown 或重新拉取整段历史。
- 长会话使用分页与必要的虚拟化；工具展开、文字选择和读屏语义需保留。加载历史采用稳定锚点，不只保存滚动像素。
- 建立固定测试样本：1,000 个对话项、10,000 行工具输出、多个后台 Agent 持续输出；记录测试设备、浏览器和数据，不能单凭微型样例判定跟手。
- 所有图标按钮有可访问名称，菜单支持键盘导航，Dialog 有焦点约束和恢复，状态不只靠颜色。流式正文不要逐 token 用 aria-live 朗读；只播报必要的开始、等待和结束状态。
- 200% 缩放、窄屏和长中文标题下不裁掉主操作。悬浮才可见的操作必须有 focus 和触屏替代。

| 状态 | 作用域／保存位置 |
| --- | --- |
| 当前 Agent | 路由中的 Agent ID，服务端校验账号 |
| 会话／队列／审批 | 服务端权威状态 |
| 草稿 | 账号＋Agent／创建上下文隔离的本地草稿，可按现有产品策略同步 |
| 阅读锚点、终端展开 | 账号＋Agent＋设备 |
| 侧栏／面板宽度 | 账号＋设备＋面板类型 |
| 项目视图、导图镜头 | 继续按账号＋项目保存，不被 Agent 跳转覆盖 |
| 返回任务上下文 | 受验证的站内返回位置与任务视图状态，不接受任意外部 return URL |

### 11.2 实施批次

1. **工作台外壳与纵向对话链路**：统一侧栏、顶栏、阅读列、输入器、审批、Task 跳转和终端切换区；接入稳定消息投影，完成 Codex 真实流程。
2. **创建、Workspace 与公共界面统一**：模板／实例选择、身份特性、独立目录预览、多 Task 关联、准确的生命周期动作；更新旧模式文案与迁移入口，并按第 4.3 节将共享控件规格应用到任务、设置、习惯和复盘页面。
3. **完整交付与多 Harness**：变更／PR、Claude／DSH 能力、原生 CLI 交接、长历史和移动端细节；视需要接入 AG-UI／CopilotKit。

批次 1 就必须覆盖 IME、账号隔离、恢复历史和基本移动布局；它们不作为最后的装饰性优化。未实现面板入口不提前上线为无效按钮。
