## 已确认的差距

| 区域 | 当前 Nexus | T3 参考与需要补齐的方向 |
| --- | --- | --- |
| 导航主次 | 大“添加任务”按钮、任务搜索、Agent 搜索、项目筛选长期叠放 | Agent 场景应以会话列表为主，创建、搜索和筛选合并到紧凑工具行；保留任务导航能力但降低其视觉占用 |
| 消息容器 | 短用户消息也撑满 85% 阅读列，时间与复制常驻占一行 | 用户消息按内容收缩到最大宽度，元信息降低常驻占用；处理连续消息的分组节奏 |
| 色阶与表面 | 深色底为灰色，输入器和消息块接近同层；基础控件沿用原站风格 | 参考当前 T3 的中性色阶、黑色画布和独立表面层级；浅色和真实主题切换也要验证，不仅修改截图 class |
| 输入器 | 基本 textarea 与一行产品文字，模型、上下文和交互反馈仍较简化 | 输入内容自适应、上下文引用、可用配置、队列和待回应入口形成整体；不为未实现能力添加假按钮 |
| 工作活动 | 工具卡片逐条展开，缺乏回合级活动收拢和产物层次 | 区分工作摘要、正在执行的动作、工具结果和最终答复，统一折叠与状态呈现 |
| 右侧上下文 | Task／变更／Workspace 通用详情栏，Workspace 以字段列表为主 | 以实际 Workspace 名、目录、分支、变更和交付动作组织紧凑上下文，减少 ID 和表单感 |
| 验收 | 功能断言、尺寸和性能测试已做；样本以人工历史消息为主 | 使用同一组完整工作样本比较空态、运行、审批、交付和错误；功能测试通过不能证明视觉对齐 |

后续视觉实现应以同状态截图、实际组件和明确尺寸进行对照，沿用 Nexus 的任务、账号和环境语义。不可把参考文档中“Nexus 建议值”当作 T3 实测值，也不可把条件支持的原生功能算成已经提供。

## 本轮先修复的已有 Agent 空白问题

生产只读核查发现，现有 Agent 是旧 Codex/tmux 接入。其最新 100 条对话投影都是连接状态，前端隐藏这些状态，却仍用它们计算分页，导致实际可读记录被挤到更早页面。

修复将状态事件从可读历史分页中排除，保持事件流游标和消息送达状态更新；旧 tmux 重叠快照只显示最近一份，原记录不删除。说明和“查看原终端”入口固定显示。此修改恢复已保存的指令／工作记录，不声称恢复此前未采集的原生聊天历史，也不重启或重建已有 Agent。
